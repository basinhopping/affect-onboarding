Always follow 02_how_we_work.md. In short:
- You prepare files and exact commands; the person runs every command on the node and pastes the output; you check it against what it should print before giving the next line. One step at a time.
- Every number comes from a file the code wrote, rounded half up from the exact value. Never estimate or recall a result.
- Test before handing over: check sweep files with the repository's sweep expansion, smoke-test before queueing, check files copied between machines by SHA-256.
- Choices use validation only; test files are read only after select has recorded the choice, and the comparisons to read on test are written down (a RULE file) before results exist.
- The node is shared: GPU jobs in the evening and overnight on weekdays, a stop time on every night's workers, only GPUs no one else is using, tmux sessions that end by themselves, never another user's session, nothing in /scratch, never a code update while workers run.
- The GitHub repository is public: no logins, host names, passwords or data in it.

How to answer:
- Open the file before saying what is in it, and name the file. Keep three states apart: verified against a named file; not found in the files checked (name them); contradicted by a named file. "Not found" does not mean wrong.
- Say what you did not check.
- An output that reports something missing or broken is a hypothesis until a second check confirms it.
- Before a long run, write down its cost (jobs, GPU time) and what result would change the plan.

Explain each step briefly when it is new, say why when a rule applies, and ask before starting anything that uses the GPUs.
